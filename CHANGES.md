1.  **Recommended: scheduled audit agent that proposes, never publishes.** A weekly (or after-every-deploy) scheduled Claude session crawls the live site, screenshots every page, checks for console errors/broken links/broken images, and diffs screenshots against the last run to catch unintended visual regressions. Findings get written as new `CHANGES.md` Open items — same workflow you're already using — so you stay the approval gate on anything it finds, rather than it silently "fixing" things. Lowest risk of the three, fits the process you've already built.

More "always-on" and catches things before they're even live, but more upfront engineering and prone to noisy false positives that need tuning.
3.  **On-demand review, manually triggered.** Exactly what happened in this session — ask for a "critical eyed developer" pass before a bigger publish. Zero standing infrastructure, but only happens when you remember to ask for it.

Recommendation is #1: it matches the CHANGES.md-as-approval-gate pattern already in place, and keeps you deciding what actually ships instead of an agent publishing on its own judgment. Say the word if you want it scheduled. Commit: 935f795.
